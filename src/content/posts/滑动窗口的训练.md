## 定长滑窗套路
窗口右端点在 i 时，由于窗口长度为 k，所以窗口左端点为 i−k+1。

我总结成三步：入-更新答案-出。

入：下标为 i 的元素进入窗口，更新相关统计量（本题为窗口内的元音个数）。如果窗口左端点 i−k+1<0，说明尚未形成第一个窗口，重复第一步。
更新答案：此时窗口长度为 k，符合题目要求，用相关统计量（本题为窗口内的元音个数）更新答案。
出：下标为 i−k+1 的元素离开窗口，更新相关统计量（本题为窗口内的元音个数），为下一个循环做准备。注：元素离开窗口后，窗口长度为 k−1。下一轮循环元素进入窗口后，窗口长度为 k。
以上三步适用于所有定长滑窗题目。

### [3679. 使库存平衡的最少丢弃次数](https://leetcode.cn/problems/minimum-discards-to-balance-inventory/)

给你两个整数 `w` 和 `m`，以及一个整数数组 `arrivals`，其中 `arrivals[i]` 表示第 `i` 天到达的物品类型（天数从 **1 开始编号**）。

物品的管理遵循以下规则：

- 每个到达的物品可以被 **保留** 或 **丢弃** ，物品只能在到达当天被丢弃。
- 对于每一天 `i`，考虑天数范围为 `[max(1, i - w + 1), i]`（也就是直到第 `i` 天为止最近的 `w` 天）：
    - 对于 **任何** 这样的时间窗口，在被保留的到达物品中，每种类型最多只能出现 `m` 次。
    - 如果在第 `i` 天保留该到达物品会导致其类型在该窗口中出现次数 **超过** `m` 次，那么该物品必须被丢弃。

返回为满足每个 `w` 天的窗口中每种类型最多出现 `m` 次，**最少** 需要丢弃的物品数量。

解法；
[贪心](/posts/%E8%B4%AA%E5%BF%83/)+滑动窗口；
依旧map记录次数：map<int,int> cnt;
贪心：
当物品 x=arrivals[i] 进入窗口时，如果发现窗口中 x 的出现次数超过 m，我们有两种选择：

丢弃刚进入窗口的物品 x。
如果窗口中还有另一个物品 x’=x，我们可以时光倒流到 x‘进入窗口的那个时刻，将 x’丢弃。
哪种选择更好？

晚丢更好，如果后面还有更多的 x，那么晚丢会让窗口中的 x 的个数比早丢更少，后面丢弃的物品数更少。

代码实现：
ans即最后次数。
int &x=arrivals[i];
if(cnt[x]==m){
	x=0;
	ans++;
}else{
	cnt[x]++;
}

滑动窗口：
注意一开始的长为 1,2,3,…,w−1 的窗口也要考察是否需要丢弃物品。

用一个哈希表（或者数组）cnt 统计窗口中的每个元素的出现次数。

元素 x=arrivals[i] 进入窗口时：

如果 cnt[x]=m，那么丢弃 x，答案加一。⚠易错点：x 在未来要离开窗口，但由于已经丢弃，不能在离开窗口时修改 cnt。可以用布尔数组标记下标 i 已丢弃，也可以直接把 arrivals[i] 改成任意不在 arrivals 中的数，比如 0，表示已丢弃（删除）。
否则把 cnt[x] 加一。
元素 x=arrivals[i+1−w] 离开窗口时：

把 cnt[x] 减一。
代码实现：
int j=i-w+1;
if(j>=0){cnt[arrivals[j]]--;}

## [1658. 将 x 减到 0 的最小操作数](https://leetcode.cn/problems/minimum-operations-to-reduce-x-to-zero/)

这题也是逆向思维，不过逆得很奇怪，是二维数组记录下标然后再滑动二维数组，他那个第一个循环有点没看懂，ds解释如下：
这个 `i- pos_list[x].size()` 是整个算法的精髓（一种叫"坐标归位"的技巧）。我拆开讲。

先看 push 的那一刻，`pos_list[x].size()` 是什么

在 push 的瞬间，`pos_list[x].size()` = **x 之前已经出现过几次**，也就是这是 x 的"第几个出现"（从 0 数起）。

```cpp
nums = [1, 2, 1, 1, 3]   // 只看 x=1

i=0, 第一个 1: size()=0 → 存 0 - 0 = 0
i=2, 第二个 1: size()=1 → 存 2 - 1 = 1
i=3, 第三个 1: size()=2 → 存 3 - 2 = 1
```

所以存进去的其实是：**`q = 原始下标 - 出现次数`**。即 `pos_list[1] = [0, 1, 1]`。

减掉这个"第几个"得到什么

关键洞察：**`q_j` 恰好等于"在第 j 个 x 前面，有几个非 x 的元素"**。

为什么？原始下标 `i` 数的是"前面**所有**元素"，而 `size()`（出现次数）数的是"前面 **x** 的个数"，两者一减 = 前面**非 x** 的个数：

```cpp
i=0 的第一个 1:  q=0  → 它前面非1的元素：0 个
i=2 的第二个 1:  q=1  → 它前面非1的元素：1 个（那个 2）
i=3 的第三个 1:  q=1  → 它前面非1的元素：1 个（那个 2）
```

为什么要减：让差值变成"杂质数"而不是"原始距离"

如果不减，直接存原始下标 `[0, 2, 3]`，那 `pos[r] - pos[left]` 就是**两个 1 之间的原始距离**——里面混着 x 和其他元素，说不清哪个是哪个。

减了之后：

```
pos[r] - pos[left] = (p_r - r) - (p_l - l) = (p_r - p_l) - (r - l)
                    = 两端的原始距离 - 中间夹的 x 个数
                    = 中间夹的【非 x】元素个数（杂质数）
```

所以第二个循环那句 `while (pos[r] - pos[left] > k)` 翻译成人话：

> **如果这两个 1 之间夹的非 1 元素超过 k 个，就把左边界往右挪。**

而 `r - left + 1` = **"杂质不超过 k 个时，x 最多能连续出现几次"**。

走一遍

`pos_list[1] = [0, 1, 1]`，k=1：

```
r=0: left=0, 0-0=0  ≤1 → 窗口1个1
r=1: 1-0=1   ≤1 → 窗口2个1
r=2: 1-0=1   ≤1 → 窗口3个1   ← 三个1之间只夹了1个杂质(2)，合法
```

输出 3：位置 0、2、3 的三个 1 之间，最多 1 个杂质，成立。

一句话总结

**`i - pos_list[x].size()` 把"原始坐标"重写成"坐标 - 出现次数"，让相邻差值从'原始距离'变成'杂质个数'**，滑动窗口才能用 `≤ k` 去限制杂质数。这是滑动窗口坐标归位的经典技巧

## [2271. 毯子覆盖的最多白色砖块数](https://leetcode.cn/problems/maximum-white-tiles-covered-by-a-carpet/)

这题挺杂的，有贪心
这数组特点就是pos[right]-pos[left]>k就要left右移，并且可以用right-left+1来代表元素量
我们既然想要两条最长的线段，就可以用一个pre数组来记录right在不同的位置时我们所能得到的最多的奖品,并且这个数组会根据我们left指针的变化而变化，即所谓pre数组就是我们在找到符合条件的right窗口后，前面所能获得的最多的奖品
pre[right+1]=max(pre[right],right-left+1);
注：[right+1]是为了避免后面的pre[right]里的right越界情况
所以最后我们的ans就是ans=max(ans,pre[right]+right-left+1);

一般要写 ans += left。

内层循环结束后，[left,right] 这个子数组是不满足题目要求的，但在退出循环之前的最后一轮循环，[left−1,right] 是满足题目要求的。由于子数组越长，越能满足题目要求，所以除了 [left−1,right]，还有 [left−2,right],[left−3,right],…,[0,right] 都是满足要求的。也就是说，当右端点固定在 right 时，左端点在 0,1,2,…,left−1 的所有子数组都是满足要求的，这一共有 left 个。
